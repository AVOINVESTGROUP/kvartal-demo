# PARTNER LAYER

## Цель
Описание механики работы с партнёрами и брокерской сетью, особенно для рынка Дубая.

## Основные задачи
- Быстрая проверка партнёров
- SLA по передаче задач
- Надёжный handoff из KVARTAL в партнёрскую сеть
- Контроль качества и отчётность

## Процесс партнёрства
1. Пользовательская задача квалифицируется
2. Назначается партнёр для рынка `dubai`
3. Партнёр принимает задачу и получает данные
4. Партнёр обновляет статус и передаёт отчет
5. KVARTAL синхронизирует результат с CRM

## Партнёрские данные
- `partner_id`
- `name`
- `region`
- `license_info`
- `response_time`
- `rating`
- `assigned_deals`

## SLA и параметры
- Время ответа: 2 часа для горячих задач
- Время подтверждения: 24 часа
- Обновление статуса: не реже 1 раза в день
- Эскалация: при отсутствии ответа > 48 часов

## Ограничения
- Передача данных должна быть минимальной
- Партнёр видит только релевантные объекты и задачу
- Конфиденциальная информация передаётся через безопасный канал
