# Единый Property Identity Registry — инструкция пользователя

Дата: 2026-07-26  
Статус: реализация подготовлена, deployment в dev ещё не выполнен

## Что это такое

Property Identity Registry — единый реестр физических объектов всей платформы Fixer.guru / KVARTAL. Это не отдельная база агентства и не отдельный кабинет.

- Один физический объект имеет одну карточку `PropertyObject` и один идентификатор IREPN.
- Несколько агентств могут работать с тем же объектом через собственные права представления и коммерческие предложения.
- Web3-токен подтверждает происхождение записи реестра. Он не доказывает право собственности на недвижимость и не заменяет юридические документы.

## Что делает партнёр

1. Войдите в существующий кабинет партнёра.
2. Откройте обычную форму «Новый объект».
3. Заполните объект, включая официальный идентификатор (для России — кадастровый номер Росреестра).
4. Нажмите обычную кнопку сохранения/публикации.

Отдельную заявку Property Identity создавать не нужно. Отдельной страницы реестра в партнёрском кабинете нет.

## Что делает система автоматически

При сохранении обычного объекта система:

1. проверяет официальный идентификатор в едином реестре;
2. если совпадения нет — создаёт один канонический объект и его IREPN identity;
3. если точное совпадение есть — не создаёт дубль, а добавляет право представления и offer текущего партнёра;
4. показывает в карточке объекта IREPN ID, статус identity и статус права;
5. создаёт разрешение на конкретную витрину в статусе `DRAFT`, если партнёр запросил публикацию.

Статус `DECLARED` означает, что партнёр заявил право. Это ещё не означает юридическую проверку платформой. Статус `VERIFIED` появляется после проверки доказательств владельцем платформы.

## Что делает владелец платформы

Откройте `platform-admin → Property Identity Registry`.

- Проверьте заявленные партнёрами права представления и укажите основание решения.
- Активируйте `PublicationGrant` только когда identity, право, offer и витрина готовы.
- Управляйте rollout по рынкам. После deployment сначала проверьте обычную форму, затем включите `NEW_SUBMISSIONS_ONLY`; publish gate включайте отдельным шагом.
- Откройте `Web3 и Safe` для Corporate Safe, token-операций и reconciliation.

Платформа не обрабатывает «заявку на создание объекта»: объект создаёт и исправляет сам партнёр. Владелец платформы проверяет право представления, публикацию и Web3-состояние.

## Corporate Safe и Web3

1. Владелец платформы создаёт EIP-712 challenge для Corporate Safe организации.
2. Safe подписывает challenge; API проверяет контрактную подпись EIP-1271 и читает owners/threshold из сети.
3. Для статуса `ACTIVE` нужны минимум два Safe owner и threshold не меньше 2.
4. Операция `MINT`, `UPDATE_HASHES`, `SUSPEND`, `UNSUSPEND`, `REVOKE` или `REASSIGN` ставится в очередь.
5. API сам не подписывает и не отправляет транзакцию: требуется IREPN Registry/Admin Safe.
6. После транзакции владелец записывает tx hash и запускает reconciliation.
7. Публикация считается Web3-verified только при `IN_SYNC`.

По умолчанию разрешена только BNB Smart Chain Testnet, chain ID `97`. Mainnet-запись заблокирована без отдельного решения, флага и change ticket. Private keys и seed phrases проект не хранит.

## Как проверить в dev после deployment

1. Убедитесь, что старая страница `/property-identity` возвращает в обычный кабинет.
2. Создайте объект через обычную форму с новым кадастровым номером — должна появиться одна карточка с IREPN ID.
3. Повторите тот же кадастровый номер из другого партнёрского агентства — новая физическая карточка появиться не должна; у второго партнёра должно появиться собственное право/offer.
4. В `platform-admin` подтвердите право и активируйте разрешение витрины.
5. Проверьте, что объект появился только на разрешённой витрине и используется offer этого партнёра.
6. Создайте Safe challenge, проверьте EIP-1271 signature и убедитесь, что 1-of-1 Safe не получает `ACTIVE`.
7. На BSC Testnet выполните mint через Registry/Admin Safe, запишите tx hash и запустите reconciliation.
8. Откройте `/verify/{IREPN-ID}` и проверьте статус, Safe и BscScan. Адрес недвижимости, документы, контакты и цена на этой странице отсутствуют.

## Безопасный порядок deployment

1. Cloud SQL backup.
2. Применить миграции — первая отключит ошибочный rollout.
3. Развернуть office-api и platform-api.
4. Развернуть partner-admin, kvartal-admin, platform-admin и web.
5. Выполнить E2E обычной формы при выключенном rollout.
6. Включить `NEW_SUBMISSIONS_ONLY` без publish gate.
7. Выполнить duplicate/rights/offer E2E.
8. Включить publish gate и проверить витрины.
9. Web3 активировать только на Testnet после привязки обоих Safe.
